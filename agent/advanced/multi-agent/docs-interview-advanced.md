# 模块 30-34 面试题精选（8 道）

## Q1. RAG 召回率突然骤降，怎么排查？
**考察**：RAG 运维。**标准**：五步——① 检索层：embedding 服务是否变更/超时（相似度分布对比）；② 索引层：最近是否有重建/删除（文档数对不上）；③ 分块层：分块器版本变化导致粒度漂移；④ 查询层：查询改写/意图分类是否回归；⑤ 数据层：语料更新引入噪声。**加分**：建立 RAGAS 评估集定期回归，骤降时先跑评估定位是"检索没召回"还是"召回了没答好"；混合检索的 BM25 通道兜底。**误区**：直接换 embedding 模型（全量重建+效果未知）。

## Q2. 多 Agent 系统中信息如何共享与隔离？
**考察**：模块 32 核心。**标准**：隔离=独立上下文/记忆/权限（每个 Agent 只见自己职责内信息）；共享=结构化消息（事件单/结论）+受控共享区（带 ACL 的事实板）。原则：共享"结论"不共享"过程"。**加分**：本项目实证（事件单 JSON 而非对话历史）；共享记忆的幻觉放大风险（标记来源与置信度）；Harness 层锁防并发冲突。**误区**：全员共享大上下文；Agent 点对点私连绕过审计。

## Q3. LLM 输出 JSON 解析失败怎么办？
**考察**：工程鲁棒性（本项目实测踩点）。**标准**：三层——① Prompt 层严格 JSON 约束+few-shot；② 解析层 extract_json（剥围栏+定位大括号）；③ 兜底层：重试一次/规则代码直接推导（结构化数据确定优先）/降级人工。**加分**：本项目 DiagnoseAgent 的代码兜底实测（LLM 失败→从诊断数据规则推导根因置信度 0.9）；structured outputs 约束解码。**误区**：只重试不兜底；把"解析失败"静默吞掉。

## Q4. 设计 Agent 平台的灰度发布方案？
**考察**：生产化。**标准**：对象三层（Prompt/Skill/模型路由规则）；机制=按流量比例分流+业务指标回看（采纳率/成功率/成本）+自动回滚阈值；基础设施=版本化仓库+评估集门禁+影子流量（新版本只记日志不出答案）。**加分**：K8s 金丝雀（ Deployment 按副本比）与 Argo Rollouts 的渐进式交付对接；用户级 sticky（同一会话不切版本）。**误区**：全量切换；没有回滚演练。

## Q5. Agent 的成本怎么优化？给一套方法。
**考察**：工程闭环。**标准**：计量归因（模块 27 on_usage）→ 优化四板斧：Prompt 精简（Token 实验，模块 26）、缓存（精确/语义/前缀）、模型路由（小模型优先+cascade）、步数控制（Agent max_steps+少步提示）。**加分**：本项目实测口径（mock 0 成本但链路真实）；cascade 的置信度升级策略；批处理 API（离线任务半价）。**误区**：只换便宜模型不改结构；缓存无失效策略。

## Q6. vLLM 为什么快？部署要注意什么？
**考察**：推理服务。**标准**：PagedAttention（KV Cache 分页管理，显存利用率大幅提升）+连续批处理（请求级动态组批）+前缀缓存。部署：OpenAI 兼容端点、GPU 显存规划（模型+KV Cache）、量化（AWQ/GPTQ）取舍。**加分**：与 Ollama/TGI 对比；多实例负载均衡+健康检查；预热的 warmup 请求。**误区**：忽略 KV Cache 显存估算；单实例裸奔无重试。

## Q7. Prompt Injection 在工具调用场景的攻击面？
**考察**：安全。**标准**：三面——用户输入注入（直接指令）、**工具返回内容注入**（网页/工单内容携带恶意指令进入上下文）、跨会话注入（共享记忆污染）。防御：输入输出过滤、工具结果标记 untrusted、敏感工具审批、最小权限。**加分**：场景二实证（外发类工具=防火墙规则强制权限裁决）；"数据与指令分离"的提示设计（引用式上下文）。**误区**：只防用户输入；认为内网工具无风险。

## Q8. 设计"网络故障诊断多 Agent 系统"。
**考察**：综合设计（对应 ops_agents.py）。**标准**：流水线拓扑（监控→诊断→工单）+结构化事件单+代码兜底+分体权限+统一审计；Manager 拓扑用于全网分片巡检；评估=链路成功率/误报率/MTTR。**加分**：本项目实测数据（事件单 EVT-xxx→光功率根因 0.9→TKT-xxx）；为什么不全部单 Agent（成本/可控性/审计）；人工升级点的设计（置信度<0.5 转人工）。
**误区**：Agent 间自由对话（不可控）；无兜底（LLM 失败全链路瘫痪）。
