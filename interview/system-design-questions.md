# 综合系统设计题（8 道）

> 每道题包含七段：需求与约束 / 架构图 / 组件与选型 / 关键数据流 / 高可用与容灾 / 成本与资源 / 面试追问应对。
> 按追问手册第 5 轮要求，这里是"可背诵的骨架 + 可展开的细节"；口头面试按 10 分钟/题组织。

## 题 1：百万级设备的通信网络智能监控平台（K8s + Flink + Agent）

**1. 需求与约束**：100 万基站/网元，每台 10-50 条 KPI/秒 → 峰值 2000 万条/s（~10GB/s 入）；告警端到端延迟 <60s；数据不丢；7×24。
**2. 架构图**：

```
百万设备 ──省级采集集群(按地市分片)──► Kafka 分级集群(地市→省,MM2)
  省 Kafka ──► Flink 集群(分片并行 200+)──► 告警 ──► ES 集群(检索) + 告警网关
                  │                              Agent 平台(Skill/MCP/Harness)
                  └──► Kafka ──► Spark 离线(画像/月报) ──► 数仓
```

**3. 组件与选型**：Kafka 按地市分片（每片区独立集群，爆炸半径隔离）；Flink Application 模式 on K8s（作业=镜像）；ES 按月索引+ILM 冷热分层；Agent 平台用本项目 Harness 架构（Skill 管理告警分析/容量规划）。
**4. 关键数据流**：设备→采集器（攒批 100ms）→ 本地 Kafka → Flink 事件时间窗口 30s（分切片 SLA）→ 告警双写；Lag 联动 KEDA 伸缩。
**5. 高可用**：采集器本地 WAL 重传；Kafka RF=3 跨机架；Flink HA+Checkpoint 到对象存储；ES 副本跨可用区；Agent 无状态多副本。容灾：同城双活 Kafka+MM2 异地。
**6. 成本**：Kafka ~40 节点、Flink ~200 slot、ES 热温冷 3 层——成本大头是存储（ILM 冷数据转对象存储降 60%）。
**7. 追问应对**："百万设备怎么分片？"→按地市+设备 hash，分片键带设备保证同设备有序；"窗口 30s 太慢？"→两级：简单阈值走逐事件 CEP，复杂聚合走窗口；"告警风暴？"→限流+分级采样+Agent 侧聚合去重。

## 题 2：实时网络安全威胁检测与自动响应（Kafka + Flink CEP + Agent）

**1. 需求**：NetFlow+防火墙日志实时检测 SYN/UDP Flood、慢速攻击；检测延迟 <30s；自动封禁需授权；攻击画像离线沉淀。
**2. 架构**：场景二的全景放大——探针→Kafka→Flink CEP（多模式规则库）→告警→Agent（MCP 下发防火墙）→Spark 离线画像反哺规则。
**3. 选型**：CEP 规则引擎化（规则=Pattern 配置，热更）；封禁接口抽象为 MCP Server（权限分级，场景二实测）；误报治理：多信号确认（纯 SYN 占比+包速率+目标集中度）。
**4. 关键流**：检测→告警（30s）→Agent 查封禁列表→审批/自动封禁→回执审计→离线画像（Top 源/波次/特征）。
**5. 高可用**：检测集群分片（按 IP hash）；封禁通道幂等+过期（30 分钟）；Agent 审计全程留痕（合规）。
**6. 成本**：NetFlow 数据量大（全量 40GB/s）→ 采样（1:100）+ 聚合（按 5 元组秒级预聚合）后进 Kafka，成本降 90%。
**7. 追问**："误封业务 IP？"→白名单+封禁 TTL+一键解封+事后审计；"检测规则怎么热更？"→规则配置中心→Flink 广播状态（broadcast state）动态加载。

## 题 3：Agent 平台的灰度发布方案（K8s 金丝雀 + ArgoCD）

**1. 需求**：Agent（Prompt/Skill/模型路由）变更可灰度、可观测、可秒级回滚。
**2. 架构**：Git（Prompt/Skill 版本）→ ArgoCD 同步 → K8s 双 Deployment（stable/canary 按副本比 95/5）→ Argo Rollouts 渐进（5%→25%→50%→100%，每步自动分析）。
**3. 关键设计**：**流量切分**按会话 sticky（同一会话不切版本）；**指标门禁**：采纳率、任务成功率、成本/会话、P99 延迟——低于基线-5% 自动回滚；**影子流量**：新版本只记录不出答案（无风险预热）。
**4. 数据流**：请求带版本标签 → 网关分流 → 分版本指标上报 → 分析器决策。
**5. 高可用**：回滚=Argo Rollouts abort（秒级）；数据层：会话上下文版本无关（上下文外置 Redis）。
**6. 成本**：canary 独占资源按 5% 预算；评估集离线跑（省在线成本）。
**7. 追问**："模型切换也是灰度？"→是，路由规则本身入 Git；"A/B 和金丝雀区别？"→A/B 看业务假设、金丝雀看风险控制，可叠加。

## 题 4：跨地市边缘-中心协同计算架构

**1. 需求**：N 个地市边缘节点（网络可能中断），数据本地闭环+省中心汇聚分析；边缘自治（断网不断业务）。
**2. 架构**：边缘=K3s（轻量 K8s）+ 本地 Kafka + Flink 小集群（本地闭环检测）；中心=完整平台（K8s+Kafka+Flink/Spark）；通道=MM2/上行压缩批传；管理=Cluster API + GitOps（ArgoCD 多集群）。
**3. 关键设计**：**边缘自治**——本地 Checkpoint+本地告警，断网时缓存上行数据（磁盘队列）；**带宽优化**——边缘预聚合（只上行告警+聚合结果，不上行原始流）；**配置下发**——Git→中心→边缘拉取（pull 模式抗断网）。
**4. 数据流**：设备→边缘检测（秒级）→ 告警本地处置 → 压缩上行（分钟级）→ 中心画像/全局视角。
**5. 高可用**：边缘双节点+自动切换；通道断续重传；中心多可用区。
**6. 成本**：边缘硬件受限于机房条件（K3s+小 Flink）；带宽是持续成本——预聚合比原始上行省 95%。
**7. 追问**："断网 2 小时会怎样？"→边缘自治处置+数据缓存，恢复后补传；中心视图显示数据延迟；"边缘升级？"→GitOps pull，分批灰度，失败自动回退本地版本。

## 题 5：电信级可靠大数据流管道（不丢/不重/低延迟）

**1. 需求**：计费级数据：不丢、不重、端到端秒级；跨机房。
**2. 架构**：生产端（WAL+幂等+acks=all）→ Kafka（RF=3/min.isr=2/unclean=false）→ Flink（Checkpoint+EXACTLY_ONCE Sink）→下游（幂等写）。
**3. 关键设计**：每跳语义对齐——生产端 at-least-once+WAL 重传、Kafka 持久化多数派、Flink 状态与位点原子、Sink 幂等（业务主键）＝**端到端 Exactly-Once 效果**；
**4. 数据流**：含失败注入矩阵（每跳崩溃的恢复行为表——本项目模块 18/20/24 的实验结论直接复用）。
**5. 高可用**：跨机房 MM2 同步+消费位移翻译；RPO=复制延迟（秒级）。
**6. 成本**：可靠性的价格=副本×2+事务延迟——计费类值得，日志类降级到 at-least-once。
**7. 追问**："不重怎么证明？"→幂等消费计数对账（输入主键数=输出主键数）；"延迟瓶颈？"→窗口/批次间隔，非网络。

## 题 6：基于 K8s 的 NFV 网络服务编排平台

**1. 需求**：VNF/CNF 生命周期（实例化/扩缩/升级/终止）、服务链（SFC）编排、多厂商镜像接入。
**2. 架构**：场景四的放大——NFV Operator（Reconcile/Finalizer/Status）+ SFC 分类器（SDN 对接）+ Skill 封装（编排工作流）+ Agent 辅助（模板推荐/异常自愈建议）。
**3. 关键设计**：CRD 抽象（NetworkServiceChain）屏蔽厂商差异；镜像仓库分厂商命名空间+准入校验（签名）；生命周期状态机（Provisioning→Serving→Draining→Terminated）。
**4. 数据流**：CR 变更→Reconcile 收敛→Status 上报→Skill 巡检（模拟流量验证链路通）→上线确认。
**5. 高可用**：每跳多副本反亲和跨机架；Operator 主备（leader election）；升级=按跳滚动+旁路导流。
**6. 成本**：VNF 资源按 SLA 分级（核心链路独占节点池）；共享链路超卖。
**7. 追问**："多厂商镜像差异？"→CRD 抽象+厂商 driver 插件；"升级失败回滚？"→按跳回滚+导流切换。

## 题 7：多租户智能运维 SaaS 平台

**1. 需求**：N 家运营商/企业租户共用平台：数据隔离、配额、计费、可定制 Skill。
**2. 架构**：接入层（租户网关：认证+路由）→ Harness 集群（多实例，租户上下文注入）→ 数据层按租户分库/分索引（ES index per tenant）→ Kafka topic 命名空间隔离 + 配额。
**3. 关键设计**：**隔离三面**——数据（分索引+查询强制租户过滤）、计算（配额+优先级队列）、Skill（租户级 Skill 仓库与版本）；**计费**：Token/工具调用/存储三维计量（模块 27 on_usage 按租户打标）。
**4. 数据流**：租户请求→网关注入租户上下文→Harness 按租户加载 Skill/模型路由→执行（权限矩阵含租户维度）→计量上报。
**5. 高可用**：无状态 Harness 多副本+分片；noisy neighbor 防护（限流+超卖保护）。
**6. 成本**：大租户独占池、小租户共享池（分时复用）。
**7. 追问**："租户数据泄露怎么防？"→存储分索引+应用层强制过滤+审计抽查+红蓝演练；"一个租户打爆平台？"→网关限流+Kafka 配额（模块 17 的 quota 机制）。

## 题 8：企业级 Agent 平台的 Harness 架构（Skill 管理 + MCP 集成 + 权限 + 可观测性）

**1. 需求**：全公司 Agent 统一底座：Skill 资产化、外部系统标准化接入（MCP）、统一权限与审计、成本可视。
**2. 架构**（模块 29 Q2 的落地版）：

```
接入层(认证/网关) → Harness 集群(会话/上下文/调度)
   ├─ Skill 仓库(版本/灰度/评估集门禁)
   ├─ MCP Client 池(多 Server 连接管理/健康检查)
   ├─ 权限中心(角色×工具×租户矩阵/审批流)
   └─ 可观测(LLM 调用/工具调用/成本三维审计+指标)
模型网关(多厂商路由+配额) | 数据层(会话 Redis/审计 DB/记忆向量库)
```

**3. 关键设计**：**Skill 生命周期**：开发（模板+评估集）→ CI（Schema 校验+回归）→ Registry（签名）→ 灰度（流量分流）→ 全量；**权限**：声明分级（read/write/dangerous）+角色矩阵+deny 硬边界（本项目 permission.py 实测）；**可观测**：每次 LLM/工具调用的三维记录（who/what/cost），trace 全链路。
**4. 数据流**：一次请求的完整审计链（本项目 e2e_demo 实证：Skill 匹配→工具裁决→执行→报告→审计 5 条）。
**5. 高可用**：Harness 无状态（会话外置）；MCP Server 池化+自动重连；审计先写（本地 WAL）再异步入库。
**6. 成本**：成本归因到租户/Skill/调用链三维度（预算告警→自动降级路由）。
**7. 追问**："为什么不直接用 LangChain？"→Harness 是平台工程（多租户/权限/审计/成本），框架只是其内一个实现选择（本项目先手写后对照，模块 28/29 实证）；"Skill 与工具边界？"→流程稳定封装 Skill、探索型保持工具（模块 29 Q3）。
