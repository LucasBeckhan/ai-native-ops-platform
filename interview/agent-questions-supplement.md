# Agent 方向面试题补充（第二轮深化，14 道）

> 配合 `interview/agent-questions.md` 与各模块文件使用。本轮主题：**RAG 实战 / 护栏工程 / 多 Agent 深水区 / Agent 平台治理**——全部有本项目可运行代码作论据。

## RAG 实战（4 道）

**Q1. 你的 RAG 检索命中率怎么评估的？为什么混合检索比单通道好？**
要点：评估集（问题→期望命中文档）跑 top-k 命中率——本项目 5/5=100%（`rag_pipeline.py` 实测）；混合=Dense 管语义（"收光很差"≈"光功率异常"）+Sparse 管精确（"eNB-1024"类术语），RRF 融合（1/(k+rank)）避免量纲问题；单向量检索对术语/编号类查询必失手。加分：命中率到 100% 后要开始看"排序质量"（MRR/NDCG）与端到端忠实度。

**Q2. RAG 分块策略怎么定？chunk_size 与 overlap 的取舍？**
要点：运维手册=结构化文本，按条目边界递归分块（本项目 120 字符+20 overlap 实测命中 100%）；chunk 太大→噪声稀释（embedding 语义模糊）；太小→上下文断裂；overlap 保跨块连续。加分：元数据过滤（设备型号/版本）比调块大小收益更大。

**Q3. 引用式回答（[来源 n]）除了反幻觉还有什么价值？**
要点：① 可核验（运维审计要求）② 失败可归因（引用错→检索层问题；引用对但答案错→生成层问题）③ 用户信任；配合"片段不足时如实说明"的兜底=完整反幻觉契约。本项目 Mock 的 RAG 回答即此契约的确定性实现。

**Q4. embedding 模型怎么选？什么时候需要微调？**
要点：维度/语言支持/推理成本/最大长度；中文运维场景选 BGE 系列或商用中文 embedding；微调的时机：领域术语检索失败率高且难以靠同义词典解决时（用"查询-正相关文档对"训练）；微调后必须全量重建索引。

## 护栏工程（4 道）

**Q5. Prompt Injection 的检测为什么不能只靠正则？你的三层是什么？**
要点：正则挡已知模式（覆盖指令/角色伪造/凭据诱导，本项目 7 组模式+启发式评分实测 4/4）；语义层（小模型分类意图）；行为层（护栏拦不住时靠权限矩阵兜底——注入成功的最终危害是"执行了什么工具"，工具白名单+审批是最后防线）。本项目 InputGuard：block≥0.8 / warn≥0.5，工具来源内容阈值更严。

**Q6. 护栏为什么是"过滤器"而不是"改写器"？**
要点：改写引入新的不可预测性（改坏了比不改更糟）；三种处置=拦截（block）/标注（warn 传递给上层决策）/脱敏（保语义的确定性替换）。本项目 OutputGuard 的 IP/手机号/密码三规则实测。

**Q7. 什么是"证据锚定"？怎么实现？**
要点：工具返回中出现的实体（设备号/告警号）登记为证据集；回答里新出现的同类实体=疑似编造→警告。本项目 EvidenceGuard 实测捕获 A-8888/eNB-9999 编造；这是"反幻觉"从 Prompt 层提升到系统层的 cheapest 手段。

**Q8. 敏感信息脱敏在 Agent 链路的哪些位置做？**
要点：三处——工具返回入上下文前（防进 LLM 供应商）、输出面向用户前（防展示泄露）、日志/审计写入前（合规）。本项目 OutputGuard 覆盖②③；①在 MCP Server 侧做字段级控制。

## 多 Agent 深水区（3 道）

**Q9. 多 Agent 链路中一个 Agent 的 LLM 调用失败，怎么办？**
要点：分层——Agent 内部（重试+代码兜底，本项目 DiagnoseAgent 的 JSON 解析失败→规则推导根因置信度 0.9 实测）；链路层（事件单重投/跳过并告警）；设计层（每个 Agent 单一职责，失败爆炸半径小）。
**Q10. 事件单（结构化消息）里应该放什么、不放什么？**
要点：放=事实数据（告警证据/诊断结果/置信度/时间戳）+唯一 ID（可追溯）；不放=原始对话（上下文污染）、猜测性结论（未标注置信度会误导下游）；大小约束（事件单 <几 KB，明细走引用）。
**Q11. 多 Agent 的成本怎么控制？**
要点：接力链天然比单 Agent 长循环省（每棒一次小调用 vs 多轮大循环）；模型分级（监控/工单用小模型，诊断用大模型）；缓存（相同事件单的重复诊断）；预算熔断（会话级 token 上限）。

## Agent 平台治理（3 道）

**Q12. Skill 数量多了以后，"路由错了"的代价与治理？**
要点：错误路由→错误 Skill 执行→浪费+误导；治理：路由正确率评估集（问题→期望 Skill）、置信度阈值（低于阈值降级通用 ReAct）、反馈闭环（采纳率反哺路由）。
**Q13. Agent 平台的"配置"有哪些？怎么管？**
要点：五类——模型路由表/权限矩阵/护栏阈值/Skill 清单/提示词模板；统一入 Git+版本化+热加载（配置中心推送）；变更评审+评估集回归。对照本项目 prompt_templates 的版本化与 mock 的确定性。
**Q14. 怎么向非技术干系人证明 Agent 系统是"可控的"？**
要点：四件套证据——权限矩阵（deny 硬边界演示）、全程审计（每次工具调用留痕）、护栏拦截记录（注入实测）、回滚机制（Skill/模型版本秒回）；用"演示攻击被拦截"代替口头保证（本项目场景二 role=engineer 审批挂起即此演示）。
